Практика после лекции: bash, FASTA и FASTQ

УСЛОВИЕ ЗАДАЧИ

1. Создайте дерево work/ из лекции одной командой mkdir -p с фигурными скобками.
2. Посчитайте последовательности в FASTA и риды в FASTQ.
3. Напишите count_reads.sh: для каждого *.fastq.gz в папке-аргументе - имя и
   число ридов; строгий режим, проверка аргумента.
4. Попросите ИИ улучшить его: вывод в TSV и parallel. Прогоните ShellCheck и
   объясните каждую строку.
5. Перепишите его на Python и сравните: длина, скорость, читаемость.

В конце: сохранить историю команд и выложить на GitHub.

СОСТАВ РЕПОЗИТОРИЯ

- work/raw/ - тестовые данные (FASTA и FASTQ.gz)
- work/scripts/count_reads.sh - базовый скрипт со строгим режимом и проверками
- work/scripts/count_reads_v2.sh - версия с TSV и parallel
- work/scripts/count_reads.py - версия на Python
- work/results/read_counts.tsv - результат подсчёта ридов
- work/results/timing_raw.tsv - сырые замеры скорости выполнения
- work/logs/history.txt - история команд

СРАВНЕНИЕ СКОРОСТИ

Данные замеров лежат в work/results/timing_raw.tsv: 25 строк без заголовка, два
столбца через табуляцию, метка варианта и реальное время в секундах (например,
"bash v1   2.149"). Это 5 кругов по 5 вариантов (bash v1, bash v2 и Python,
каждый из последних двух при 1 и 8 потоках), варианты внутри круга запускались
по очереди. Тест: 6 файлов FASTQ.gz по 200 000 ридов (около 8 МБ каждый), WSL, 8
ядер. Ниже приведены медианы по этим данным.

- Быстрее всего bash v2 с 8 потоками: 0.94 с. Это примерно в 2.8 раза быстрее
  последовательной v1 (2.65 с) и в 3.4 раза быстрее v2 с одним потоком (3.18 с).
- Python при равном числе потоков медленнее bash v2: при 8 потоках 2.45 с против
  0.94 с (примерно в 2.6 раза, проигрыш в каждом из 5 кругов), при одном потоке
  4.07 с против 3.18 с (примерно на 28%).
- По сравнению с v1: Python с одним потоком медленнее примерно в 1.5 раза, а с 8
  потоками примерно равен ей (2.45 с против 2.65 с).
